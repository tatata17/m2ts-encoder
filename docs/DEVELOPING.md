# 開発メモ

## ファイルの役割
- `m2ts_encoder.pyw` … 本体。`APP_VERSION` が版番号。
- `version.json` … 最新の版番号・変更内容と、本体の SHA-256(アプリの更新が読みに来る)。手で書かない。
- `CHANGELOG.md` … 更新履歴。
- `tools/release.py` … 公開前の確認(自動テストを含む)と、`version.json` の書き出し。
- `tests/` … 自動テスト。`python tests/run_tests.py` で実行する(下の「自動テスト」を参照)。
- `PLUGINS.md` … プラグイン(手元で足す拡張機能)の作りかた。プラグインの実物は、このリポジトリに入れない。
- `docs/index.html` … 使い方のページ(GitHub Pages で公開)。
- `docs/plugins.html` … プラグインの説明のページ。デザイン(`<style>`)と共通スクリプトは、使い方のページと同じ内容にそろえる。プラグインのしくみを変えたら、このページと `PLUGINS.md` も直す。
- `docs/sitemap.xml` … 検索エンジン向けのサイトマップ。

## 公開の手順
1. `m2ts_encoder.pyw` を直し、`APP_VERSION` を上げる
2. 起動して確かめる
3. `python tools/release.py "更新内容のひとこと"` … 確認して `version.json` を書く
   - 構文エラーがある・版番号が上がっていない・本体が小さすぎる・自動テストに失敗した、のときは、何も書かずに止まります
   - 本体を変えたら、同じ版のままでも必ずもう一度実行します
4. `CHANGELOG.md` と使い方のページの「更新履歴」に追記する
5. commit して `main` に push する

## 自動テスト
以前は動いていた機能が、あとの修正で壊れていないかを確かめるテストです。

- 実行: `python tests/run_tests.py`(全部)/ `python tests/run_tests.py sort`(名前に sort を含むファイルだけ)/ `-v` で1項目ずつ表示
- `tools/release.py` が、`version.json` を書く前に必ず実行します。1つでも失敗すると、何も書かずに止まります(とばす方法は用意していません)
- 失敗したときは、最後に「失敗したテスト」として、項目・内容・原因をまとめて出します
- 録画データ・実機の GPU・ffmpeg は使いません。画面も開きません(tkinter は、にせものに差しかえて本体を読みこみます)
- 設定・ログ・出力は、テスト専用の一時フォルダに作り、終わったら消します。実際の設定ファイルや録画には、さわりません。テストがリポジトリの中のファイルを書きかえたときは、それも失敗として知らせます
- 公開の作業をする環境(Linux)で動くことを確かめています。Windows でそのまま動くことまでは、確かめていません

| ファイル | 確かめること |
|---|---|
| `test_filenames.py` | 空白・カンマ・記号を含むファイル名(バッチの `%1` の書き方、バッチへの渡し方、できあがりの名前、同名のときの連番、スキャン) |
| `test_cuda_retry.py` | GPU でのデコードに失敗したときの、やりなおしの順番(スレッド1 → 分割 → CPU)と、ログの読み分け |
| `test_sort.py` | チャンネル別・作品ごとの仕分け(作品名の決め方、覚えた規則、仕分け済みは動かさない、移動と元に戻す) |
| `test_settings.py` | 設定ファイルの保存と、壊れたときの復旧(`.bak`)、旧名の設定の引きつぎ |
| `test_cleanup.py` | 失敗・中断のあとの片づけ(作りかけを残さない、前からあるファイルを消さない) |
| `test_update.py` | アップデートの照合(`release.py` とアプリの SHA-256 の計算が同じ、テスト失敗で公開が止まる) |
| `test_env_setup.py` | 環境セットアップ(ffmpeg の導入の流れ)と、プラグインフォルダの場所 |

機能を足したり、不具合を直したりしたら、それを確かめる項目をここに足します。画面の見た目と、実機の GPU・ffmpeg・バッチ(cmd.exe)の実際の動きは、自動では確かめられないので、これまでどおり起動して確かめます。

## SHA-256 について
- `version.json` の `sha256` は、改行を LF にそろえた本体の SHA-256 です。
- アプリは更新のとき、ダウンロードした本体を LF にそろえてから照合します(`download_update_source`)。公開側とアプリ側の計算を、片方だけ変えないでください。
- `*.pyw` と `*.py` は `.gitattributes` で LF に固定しています。

## 使い方ページ
m2ts-encoder / avs-maker / syncdub の3つの使い方ページは、同じデザイン・同じ書き方でそろえています。どれか1つを変えるときは、他の2つと食い違わないようにしてください。
